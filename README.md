# Кадастр.Помощник — чат ИИ + анализ технических планов

Проект для развёртывания как единый Vercel project. Включает статический сайт, чат-помощник (`/api/chat`) и анализ загруженных документов (`/api/analyze`).

## Что работает после настройки

- Чат-помощник по кадастровым работам с контекстом заполненной карточки и недавней историей диалога.
- Предварительный ИИ-анализ XML, TXT, JSON, PDF и DOCX в пределах ограничений интерфейса.
- Локальная проверка синтаксиса XML.
- Карточки объектов, поиск и резервные копии в браузере.

## Развёртывание для пользователя без терминала

1. Скачайте ZIP проекта и распакуйте архив. Внутри должны быть `index.html`, `README.md`, `.gitignore`, `.env.example` и папка `api` с `chat.js` и `analyze.js`.
2. На GitHub создайте новый репозиторий. Лучше сделать его Private.
3. Загрузите **содержимое распакованной папки** в корень репозитория. Проверьте, что `index.html` лежит прямо в корне, а файлы функций — в `api/chat.js` и `api/analyze.js`.
4. На Vercel войдите через GitHub, нажмите **Add New → Project**, импортируйте созданный репозиторий и нажмите **Deploy**. Для простого HTML/Node API обычно не нужна отдельная команда сборки; используйте настройки, которые Vercel обнаружит автоматически.
5. В Vercel откройте **Project → Settings → Environment Variables** и добавьте следующие переменные для Production (а Preview — при необходимости):
   - `OPENAI_API_KEY` — секретный ключ, созданный на платформе OpenAI API.
   - `APP_ACCESS_PASSWORD` — длинный уникальный пароль, который пользователь будет вводить при первом обращении к ИИ в этой вкладке.
   - `OPENAI_MODEL` — `gpt-4.1-mini` (необязательно; удалите переменную, чтобы использовать значение по умолчанию).
6. Сохраните переменные и выполните **Redeploy**: изменения environment variables применяются к следующим deployments.
7. Откройте выданный адрес `*.vercel.app`. Сначала зайдите в **ИИ-помощник**, задайте тестовый вопрос. Затем откройте **Проверка техплана**, загрузите тестовый XML без персональных данных и нажмите **Анализ ИИ**.

## Важно про расходы и секреты

ChatGPT и API оплачиваются отдельно. Проверьте биллинг и лимиты до тестирования. Никогда не вставляйте `OPENAI_API_KEY` в `index.html`, не отправляйте его в чат и не добавляйте реальный ключ в репозиторий. Если ключ случайно попал в GitHub, отзовите его и создайте новый.

`APP_ACCESS_PASSWORD` — простая общая защита, а не полноценные индивидуальные аккаунты; для публичного коммерческого сайта нужно дополнительно настроить ограничение доступа, лимиты запросов и мониторинг расходов. Установите Vercel Deployment Protection или иным способом ограничьте доступ к адресу сайта, если он предназначен только для семьи/сотрудников.

## Ограничения проверки

ИИ-анализ — вспомогательный и может ошибаться. Проект не выполняет полную официальную валидацию по каждой актуальной XSD-схеме Росреестра, не обращается в ЕГРН и не гарантирует принятия документа. Не загружайте сведения, которые запрещено передавать внешнему API; удаляйте ненужные персональные данные и не используйте реальные электронные подписи в тестах.
